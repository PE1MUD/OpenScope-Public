# Contributing to OpenScope

Thank you for your interest in OpenScope.

## Philosophy

OpenScope aims to be:

- technically correct;
- easy to understand;
- pleasant to maintain.

Readable code is preferred over clever code.

## Before submitting changes

Please ensure:

- the project builds without warnings;
- the application starts correctly;
- new functionality is reasonably tested;
- code follows `docs/coding-style.md`.

## Commits

Keep commits small.

One logical change per commit.

Write commit messages in the imperative tense.

Examples:

- Add waveform renderer
- Introduce MainWindow class
- Fix frame timing

## Pull requests

Describe:

- what changed;
- why it changed;
- any known limitations.

## Issues

When reporting bugs, include:

- OpenScope version
- Windows version
- Capture hardware
- Steps to reproduce
- Expected behaviour
- Actual behaviour

Screenshots are always appreciated.

## Questions

Design discussions and improvement suggestions are welcome.
